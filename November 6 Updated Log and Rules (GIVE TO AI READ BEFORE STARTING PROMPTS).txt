1. DEPLOYMENT METHOD — READ THIS FIRST
================================================================================
- Live site: https://scholaria-production-4e06.up.railway.app
- GitHub auto-deploys to Railway on every commit to the main branch.
- User uploads files via GitHub.com web interface only (drag-and-drop or file picker).
- CRITICAL: Subdirectory files (e.g. js/modules/repository/materials.js) will NOT
  upload correctly if you use the root-level file picker. The user must navigate
  INTO the subfolder on GitHub.com first, then upload.
- To upload everything at once: GitHub repo → "Add file" → "Upload files" →
  drag the entire local Scholaria folder onto the drop zone. This uploads all
  files including subdirectories in one commit.
- Always tell the user EXACTLY which file to upload and to which path on GitHub.
- Railway redeploys automatically after each GitHub commit (takes ~1-2 min).
- After redeploy, always test in an InPrivate Edge window with hard refresh (Ctrl+Shift+R).

6. CRITICAL RULES FOR ALL AI (DO NOT BREAK)
================================================================================
- NEVER delete or drop any database table or existing user records.
- Supabase JS v2 query builders are NOT native Promises. NEVER chain .catch()
  directly on them. Always use: try { await db.from(...) } catch(err) {}
- Supabase messages_body_check: char_length(body) >= 1 AND <= 4000. NEVER store
  raw base64 dataUrl strings in the database body column.
- Attachment payloads must never store raw base64 dataUrl strings in the DB body column.
- Always include { ssl: { rejectUnauthorized: false } } when using the pg package with DATABASE_URL.
- Use 'npm.cmd' instead of 'npm' in PowerShell on this Windows environment.
- Python is NOT installed on this machine. All scripts must be Node.js.
- The back button in login.html must remain an inline SVG — never an emoji or text icon.
